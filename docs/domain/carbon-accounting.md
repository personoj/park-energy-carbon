# 碳核算设计

状态：设计约定；适用标准、地区、行业、边界及官方因子尚未确认。当前没有正式核算实现。

## 核算运行的输入

每次 run 固定：组织/运营边界、园区、期间与时区、核算方法版本、活动数据快照、因子版本、单位换算版本、数据质量、发起人与代码版本。结果以精确十进制计算，明确舍入位置；不由 LLM 自由生成正式数值。

`活动数据 × 排放因子` 仅是部分条目的基本结构。具体气体、GWP、间接能源、分摊和特殊过程由选定的方法描述。kgCO₂ 与 kgCO₂e 不混用，范围分类由方法和边界决定。

## 因子与方法

因子具有来源文档和定位、发布机构、地区、适用行业/能源、有效期、单位、数值、版本、审核状态。缺失或不适用的因子阻止正式发布；Agent 可以建议候选，不能把生成的因子当作官方来源。

位置法与市场法分别建结果维度。新能源发电、绿电凭证、储能和上网的处理依赖所采用规则，不直接以“可再生”标签认定零排放。GHG Protocol 的 Scope 2 Guidance 区分位置法和市场法并对契约工具规定质量要求；具体项目不因引用它就自动采用该标准。

参考：[Scope 2 Guidance](https://ghgprotocol.org/scope-2-guidance)。查询日期：2026-10-13。标准变化通过新增方法版本处理，不回写历史运行。

## 结果生命周期

`draft → validated → published → superseded`

- Agent 可创建草稿和触发确定性计算；发布由拥有发布权限的业务流程执行。
- 发布前校验边界完整性、缺测、单位、因子适用性、重复计量和证据。
- 发布记录不可覆盖；更正生成新版本并引用旧版本。
- 必须能解释总量如何汇总到条目，再追溯到活动数据、导入批次和因子。
- 减排预测、避免排放、抵消量与排放清单分开，不能自动净额相减。

验收重点：同一快照和方法得出相同结果；修订数据产生新运行；没有因子时显示无法核算，而非返回零。
