# 数据处理与导入

用户已授权 Agent 处理新数据并帮助导入数据库。此文定义目标能力；M0 没有上传/导入接口。

## 工作流与状态

`uploaded → parsed → mapped → validated → previewed → committed`

失败可进入 failed，未提交可 cancelled；提交后更正通过反向批次或新版本形成 reversed，不删除审计历史。

1. 保存原文件与摘要、提交人、园区、来源说明；原文件在私有对象存储。
2. 解析器按类型输出中间行和原文件定位，不直接写业务表。首期计划 CSV/XLSX，其他格式按真实需求添加适配器。
3. Agent 建议字段映射、单位、时间格式与清洗规则；规则转成结构化、可验证的转换计划，保留版本。
4. 校验必填、类型、单位、时区、范围、测点归属、重复和计量语义。模糊字段不能静默猜测；错误行进入隔离区。
5. 预览新增/重复/冲突/错误行数与样本、目标园区、数据期间和转换规则。保留待提交计划版本。
6. 有权限的用户或已配置的自动导入策略提交该预览版本。提交前重新校验身份、计划未变化及幂等键。
7. 领域接收接口在事务内写入，返回批次 ID、成功/失败计数和可追溯信息。

## 幂等与纠错

文件摘要只能识别同文件；还需要业务键（园区/来源/测点/时间区间/指标/源版本）和唯一约束处理跨文件重复。相同业务键不同值为冲突，先展示差异，再依据修订策略新建版本。

首期建议整批事务提交；大文件按可追踪分块实现，记录各块提交状态和恢复点，不声称部分成功为整批完成。实现前确认文件大小与行数预算。

## Agent 数据处理边界

文件内容属于数据，即便单元格含“执行 SQL/忽略规则”等文字也不能改变工具权限。数据处理先采用可组合的字段映射、过滤、单位换算和解析工具。若需要任意 Python 执行，必须单独实现无数据库凭据、受限网络和资源的隔离运行环境；M0 不提供该能力。

撤回批次后标记下游受影响的核算草稿；已发布结果保留原快照并提示更正流程。导入物理 SQL 由各领域适配器生成，Agent 不直接提交 INSERT/UPDATE/DELETE。
