# 产品范围

状态：用户目标已确认；以下模块拆分为实施方案。最终核算标准、场站清单、实际测点规模仍待确定。

## 核心流程

园区总览 → 建筑/厂房 → 设备 → 指定期间能耗/碳排/告警。数据人员或 Agent 将新数据解析、清洗、校验并预览，形成可追溯的导入批次。核算人员或 Agent 选择边界、方法和因子版本，运行核算并保存草稿；正式发布通过业务权限与复核流程。

## 模块范围

- 资产与计量：园区、建筑、区域、设备、测点、计量拓扑、映射历史。
- 新能源：首批设计覆盖光伏、储能、充电负荷、购售电；实际设备类型以现场清单确认，允许扩展风电、热泵、冷热源。
- 能源分析：电量与功率、分项统计、能源流平衡、数据质量。
- 碳核算：活动数据、因子库、方法版本、边界、草稿/发布、可复现结果。
- 数据导入：文件、字段映射、单位/时区、校验、预览、幂等提交、批次追溯。
- Agent：数据目录查询、受限 SQL、处理方案、导入工具、核算工具与解释。
- 3D：模型版本、资产映射、选择/定位/高亮；场景与业务分离。
- 平台基础：身份、园区数据授权、审计、告警。

## 当前不包含

Docker、生产部署、设备远程控制、能源交易执行、自动发布正式碳报告、任意数据库管理 SQL。当前初始化仅提供合成演示和工程基线。

## 在相应里程碑前确认

1. 园区所属地区、行业、组织边界、报告用途和适用核算标准。
2. 新能源设备、计量拓扑、数据来源、采样频率、测点数量和历史年限。
3. 多园区/多组织授权关系、角色、发布责任和自动导入策略。
4. 模型来源、是否有真实 GIS 需求、目标浏览器/GPU/分辨率与性能预算。
5. Agent 模型供应商、允许传出的数据范围、文件规模与保留策略。
6. 许可证、协作成员、正式开发数据库位置。

这些问题不阻塞工程初始化，但不得用未经确认的默认值开展正式核算或真实数据接入。
