# ADR 0001：协作基础与扩展边界

日期：2026-10-13。状态：初始化实现选择；用户已确认目标、公开新仓库、Agent 能力和低耦合要求，未逐项指定依赖版本。

## 决定

使用 React/TypeScript/Vite、Three.js/R3F、NestJS，pnpm 工作区；PostgreSQL 为后续数据目标。初期模块化单体，以业务模块和端口隔离数据库、模型供应商、3D 与接入协议。当前只安装运行骨架所需依赖。

## 原因与代价

统一 TypeScript 方便跨端契约和多人协作；明确模块所有权以控制共享仓库耦合。依赖边界检查提供早期反馈，但不能自动保证语义设计正确。SQL/核算引擎保留确定性和权限边界，Agent 只编排受控工具。

## 扩展条件

- 有真实 GIS 需求时评估 Cesium；不因“园区”二字预装第二引擎。
- 根据时序规模引入 TimescaleDB；根据长任务与重试需求引入 queue/worker。
- 根据模型供应商与工具协议引入 provider adapter/MCP adapter。
- 根据团队真实共享组件引入 UI 包；不提前建立 common 大包。
- Docker 暂缓。Python 仅在解析/计算库确有需要时作为适配器或独立服务，不放入首版运行依赖。

依赖采用精确版本和 lockfile。后续更新通过独立 PR 说明兼容性与验证，不自动追随 latest。
